# Luma Studio 产品规格（冻结）

> 本文件是产品定位、范围与能力状态的唯一来源。其他文档与本文件冲突时，以本文件为准。
> 基线：仓库 `NextVariable/luma-studio`，分支 `dev/trae-luma-v05`，PR #5，HEAD `236f5f55be94ecb7c6ba05fd67b1c32e59c12b14`。

## 1. 定位

Luma Studio（流幕）是一款**镜头驱动、具有视觉反馈与选择性返工能力的 AI 原生影视导演工作台**。

- 产品类别：**AI Director Studio**
- 技术架构：Domain-specific Agentic Filmmaking Harness
- 核心用户：具备一定生成经验的独立 AI 影视创作者
- 核心需求：减少生成偏差、人工审片负担与无效返工
- 核心创新：**Cinematic Debugger**——基于真实视觉观察的约束检查、修改差异、影响分析与选择性返工

产品面向"一集一集做完"的连续创作，而不是单张图片或单条视频的生成工具。

## 2. 参考与边界

体验参考 LibTV；镜头组织参考 LTX Studio；真实创作流程参考 WorkRally；开源工程参考 Toonflow；技术思想参考 Google VQQA、CANVAS、CineCrew。

**不完整复刻任何上述产品。** 上述名称只用于校准体验与技术判断，不构成功能对标清单，也不作为重建现有模块的理由。

VQQA 与 CANVAS 是 Visual Critic 阶段的技术参考，用于设计"观察—检查—定位"的画面复核方式；本轮不引入其模型、服务或数据结构，也不据此重建现有模块。

## 3. 非目标（本轮及可见阶段）

- 不开发完整无限画布
- 不开发三维引擎
- 不重写前端
- 不重建 Agent Framework
- 不新增通用 MCP 平台
- 不扩大模型供应商范围
- 不重建 FilmSpec、World State 或单镜返工系统
- 不提前开发 Visual Critic

## 4. 技术路线（冻结）

保留现有架构：Python、SQLite、Vanilla JavaScript、FFmpeg、Dify，以及现有供应商适配器、任务队列、资产与候选系统。

| 产品概念 | 现有实现载体 | 说明 |
| --- | --- | --- |
| FilmSpec | `luma/creative.py`、`creative_spec` | 镜头级创作规格，不另立数据结构 |
| World State | `luma/continuity.py`、资产绑定、连续性状态 | 后续再补真实视觉观察 |
| Visual Critic | `luma/quality.py` | 后续主要新增能力，复用现有审核基础 |
| Cinematic Diff | `studio.py` 的 `revision_comparison`、`revision_media_impact`、`revision_preview`、`apply_job` | 已用于单镜返工，不重建 |
| 候选比较与人工确认 | `web/js/shots.js`、质量系统 | 保留现有交互 |

新名称只描述能力，不作为重建已有模块的理由。

## 5. 能力状态

状态口径：**已实现**＝代码存在且有回归测试覆盖；**已本地验证**＝在不产生供应商费用的环境中实际跑通；**未验证**＝真实云端链路尚未通过端到端验收；**计划**＝尚未开发。

### 5.1 已实现

- 作品、分集、镜头、对白编辑；本地素材导入与预览
- 资产多版本、参考视图与人工批准；未批准视图的生成门禁
- 制作准备：片段划分、模型能力校验、参数、参考图与冻结
- 报价、本机授权次数、报价有效期、去重与单次提交
- 任务队列、中断恢复、`UncertainRun` 待核实与人工对账
- 供应商适配：Dify、OpenAI 直连、fal、火山方舟 Seedream、阿里云百炼 Wan、MiniMax 海螺
- 候选入库、比较、选用；制作证据与质量评分
- 单镜返工：修改前后差异、画面/音轨影响分析、确认后应用
- 成片清单、阻塞跳转、MP4 导出（选用画面、独立音轨、可切换字幕）

### 5.2 已在本地验证

- 上一轮回归：Python 与 JavaScript 测试全绿、`ruff` 通过、CI 4/4
- 导入素材 → 复核 → 修改 → 重导出整条本地链路（FFmpeg 实跑，无模型凭据）
- 隔离库中的报价、授权、批准门禁与请求构造（未发出付费请求）

### 5.3 未验证

- 真实 Seedream 生图：请求、响应解析、候选入库、界面查看
- 真实 Wan 图生视频：首帧上传、异步任务查询、媒体下载、候选播放
- 一张真实生成的定妆图经人工批准并绑定镜头后再进入分镜生成
- 完整云端生成成片（分镜 → 首帧 → 视频 → 导出）的端到端验收
- 供应商实际账单与本地预计费用的一致性

### 5.4 计划（不在 M0/M1）

- Visual Critic：基于真实视觉观察的约束检查
- World State 的视觉观察补全
- Cinematic Diff 的差异解释与影响分析增强

## 6. 阶段路线（M0–M5）

| 阶段 | 目标 | 进入条件 | 完成标准 |
| --- | --- | --- | --- |
| M0 | 产品规格冻结 | 产品方向确认 | 本文件、AGENTS.md、README 定位一致 |
| M1 | 真实生成链路技术验收 | 隔离库与供应商凭据就绪 | 一次真实 Seedream 生图自动入库并可查看；一次真实 Wan 图生视频完成提交、查询、下载、入库与播放 |
| M2 | Visual Critic 最小闭环 | M1 通过 | 对候选画面输出结构化观察与约束检查，接入复核界面，复用 `quality.py` |
| M3 | Cinematic Diff 增强 | M2 通过 | 修改差异可解释到镜头、资产与参数层，影响分析能指导选择性返工 |
| M4 | World State 视觉补全 | M3 通过 | 连续性状态纳入真实视觉观察，跨镜一致性可检查 |
| M5 | 云端成片端到端 | M4 通过 | 分镜 → 首帧 → 视频 → 成片全链路真实跑通并导出 MP4 |

M1 的技术验收与正式样片美术质量解耦：定妆图美术质量未达标不阻塞独立的视频技术测试，但任何产物都不得自动批准、自动采用或自动绑定镜头。

## 7. 当前验收状态

真实生成链路停在凭据配置：界面已有"连接图片与视频服务"入口，但隔离验收库未配置 `ARK_API_KEY` / `DASHSCOPE_API_KEY`，因此未发出任何付费请求，实际费用为 0。

模拟响应、供应商请求记录与离线测试均不计为真实生成成功。真实产物必须能给出文件路径、格式、尺寸与 SHA256。

## 8. 变更规则

- 本文件冻结后，新增产品概念先改本文件，再改代码。
- 任何"新框架 / 新引擎 / 新平台"提案默认不做，除非能证明现有模块无法完成同一目标。
- 每轮只执行明确列出的阶段；阶段结束后停止，不自行进入下一阶段。
